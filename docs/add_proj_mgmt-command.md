# `/add_proj_mgmt` カスタムスラッシュコマンド

りさだむ杯・wilberry・ComfyUIなど、project-tracker以外のプロジェクトで作業しているセッションから、
「タスク更新してください」と都度伝えなくても、直近の作業内容をこのリポジトリの `data/tasks.json` に
反映できるようにするためのClaude Codeカスタムスラッシュコマンド。

project-trackerはGitHub Pages専用のクラウド環境からは他リポジトリを触れないため、コマンド本体は
リポジトリには置かず、ユーザーのPC側 `~/.claude/commands/add_proj_mgmt.md` に配置して使う
（グローバル配置なので、どのプロジェクトのセッションからでも `/add_proj_mgmt` として呼び出せる）。
このファイルは配布した内容の控え・仕様メモとして残している。

## 使い方

引数なしで `/add_proj_mgmt` と打つだけ。Claudeがそのセッションの直近の作業を自分で要約し、
`data/tasks.json` の中から該当タスクを特定した上で `gh` CLI経由のGitHub API操作だけで
（ローカルにこのリポジトリをcloneせずに）直接コミット・pushする。

## 挙動の要点

- 対象タスクの特定に自信が持てない場合（複数候補・該当なしなど）は、独断で更新せず必ずユーザーに確認する
- `history` 配列の先頭に要約を追加し、`updatedAt` を更新
- `status` が「未着手」のときのみ「進行中」に変更（進行中・完了はそのまま）
- `data/tasks.json` 以外のファイルには触れない

コマンド本体（配布版）は以下の通り。

```markdown
---
description: このセッションでの直近の作業を project-tracker (CitronStudio/project-tracker) のタスク管理サイトに反映する
---

このセッションで直近に行った作業内容を、GitHubリポジトリ `CitronStudio/project-tracker` の
`data/tasks.json` に更新履歴として記録してください。**ローカルにこのリポジトリをcloneせず**、
`gh` CLI経由のGitHub API操作だけで完結させてください（`gh auth status` で認証済みであることが前提）。

## 手順

1. `gh api repos/CitronStudio/project-tracker/contents/data/tasks.json` で現在の
   `data/tasks.json` の内容（`content`をbase64デコード）と `sha` を取得し、JSONとしてパースする。

2. このセッションで直近に行った作業を1〜3文程度で簡潔に要約する（何のプロジェクトの、何をしたか）。

3. 要約内容と、取得したタスク一覧の `title` / `project` フィールドを照らし合わせて、
   最も合致するタスクを1件特定する。
   - 引数（`$ARGUMENTS`）が指定されている場合は、それを対象プロジェクト/タスクの
     手がかりとして優先的に使う。
   - 自信を持って1件に絞り込める場合のみ、そのまま次に進む。
   - 該当タスクが複数考えられる、またはどれにも該当しない（＝新規タスクの可能性がある）場合は、
     独断で決めずに、候補のタスク名を挙げてユーザーに確認する。新規タスクとして追加すべきか
     どうかも合わせて確認する。

4. 対象タスクを特定できたら、そのタスクに対して:
   - `history` 配列の**先頭**に `{ "date": "<現在時刻のISO 8601文字列>", "note": "<手順2の要約>" }`
     を追加する（unshift。既存のhistoryは残す）。
   - `updatedAt` を現在時刻に更新する。
   - `status` が `"未着手"` の場合のみ `"進行中"` に変更する（`"進行中"` `"完了"` の場合はそのまま
     変更しない）。
   - 他のフィールド（`id` / `title` / `type` / `project` / `repo` / `tags` / `createdAt`）は
     変更しない。

5. 更新後のJSON全体を、既存のインデント（2スペース）・改行スタイルに合わせて整形し、
   `gh api -X PUT repos/CitronStudio/project-tracker/contents/data/tasks.json` に対して
   base64エンコードした内容・手順1で取得した `sha`・コミットメッセージ（例:
   `<タスク名>: <要約の短縮版>`）を渡し、`main`ブランチに直接コミットする。

6. 完了したら、更新したタスク名・追記した内容・コミットのURLを2〜3行でユーザーに報告する。

## 注意事項

- `data/tasks.json` 以外のファイルには一切触れないこと。
- 複数のプロジェクトにまたがる作業だった場合や、対象タスクの判断に少しでも迷う場合は、
  必ずユーザーに確認してから進めること（先走って間違ったタスクを更新しない）。
- 日本語を含むため、base64エンコード/デコード時に文字化けさせないよう注意すること
  （UTF-8バイト列として扱う）。
```
